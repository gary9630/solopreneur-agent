Problem

One person. Too many systems.

The solopreneur bottleneck is not ideas. It is the daily handoff from conversation to CRM to quote to delivery work to stakeholder update.

Incoming signal

A message, business card, or customer request arrives while the operator is away from the desk.

Manual translation

Contact, opportunity, quote, invoice draft, tasks, and updates all require repeated data entry.

Trust boundary

Live automation must be useful without silently committing risky business actions.

pain point: sales-to-delivery context switching 02 / 13
Product

AI assistant as a governed operating layer.

OpenClaw decides the next safe action. The host gateway executes only approved tools. Odoo remains the system of record.

Safety Contract

Live mode is a two-key turn.

Every live write requires operator approval in the prompt and host-level opt-in in the process environment.

live gateoperator + host
# host-side process
LIVE_WORKFLOW_ENABLED=1 make tool-gateway

# tool argument
{
  "run_id": "acme-live-001",
  "message": "Create Odoo draft artifacts...",
  "live": true
}

# invariant
invoice.state == draft
deal.stage != won

Judging Story

Not a chatbot. A governed business operator.

The demo hits a daily solopreneur pain point, shows real live system writes, keeps high-impact actions gated, and uses NemoClaw/OpenClaw as the agent runtime instead of a thin API wrapper.

Business depth

CRM, Sales, draft invoice, delivery tracking, stakeholder update, and audit trail.

Human opt-in, host gate, draft-only invoices, no deal-won mutation, auditable refs.
